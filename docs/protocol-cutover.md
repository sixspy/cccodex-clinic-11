# 协议切流 · 败例清单与双方案骨架（动笔之前）

题面病灶：方案版本「生效」之后，抓取仍绑旧协议字段、字段质控按旧版扫描、缺口补采吃进错版行。
根因：读侧（开批 / 抓取 / 质控 / 补采）直接读 `protocols` 表的「生效」行，版本一切，读侧跟着漂移，没有任何落点把"哪个中心按哪版采"钉死。

本题只看**协议切流**：新增协议切流服务，挂到试验中心列表，串好邻页（访视批次）。

## 双方案骨架（两案备齐，只落定一边）

### 甲 · 快照表（选定边 ✅）

- 落 `protocol_cutovers` 快照表：以**当场键**（`site_id`，每中心一条现行）封死，行内冻结
  方案编码 / 版号 / 必填字段 / 访视编码，并贴**指纹**（sha256 印记）。
- 读侧（开批 / 模拟抓取 / 追加行 / 合格入库 / 质控扫描 / 补采）**只读本张快照表**，
  **拒回刷**：方案表再翻牌，落点不跟动，只认显式提交的新切流。
- 再切流时旧行转**封存**（只复核、不回刷），新行接任**现行**，修订号 +1。
- 并发以**修订号钉点**（乐观锁）：提交带期望修订号，不符即 409 冲突，绝不双成功互冲。

### 乙 · 归档层 + 新旗（未选定，仅骨架，不落代码）

- 过期档送入归档层（`protocols` 过期行整体搬入 archive 表），现行读侧改读"新旗"
  （protocols 上的 current 标记）。
- 读侧立刻分叉：旧引用读归档层、新引用读新旗，需复核期双跑对账。
- 不选原因：读侧分叉期两轨并存，与"勿并存轨"硬冲突；搬档动存量，回滚代价高。
- **乙侧骨架不进代码库**，未用骨架残留即挡收工。

## 定边

甲边先落定收口。读引用在试验中心列表处分叉为**切流徽标**（只读快照表），
不再并列展示"生效方案"引用（勿并存轨）。

## 败例清单（出现任一即判失败）

1. 中心**无切流落点**却仍开批 / 抓取 / 入库 —— 败。
2. 试验中心列表**切流徽标独亮**、但快照表无对应落点行 —— 败。
3. 落点**印记校验对不齐**（指纹与冻结字段不符）却仍放行读写 —— 败。
4. 批次版号与中心落点**拧花**（不一致），旧协议抓取 / 入库 / 质控 / 补采仍放行 —— 败。
5. 两侧同事争修切流，无钉点锁导致**双成功互冲** —— 败。
6. 读侧绕过快照表、直读 `protocols` 生效行 —— 败。
7. 封存档被回刷成现行 —— 败。
8. 乙侧（归档层）骨架残留在代码里 —— 败。
9. 切流闸失败原因说不清（无明确中文报错）—— 败。

## 闸口与页面分工

- **试验中心页**：切流徽标列（落点方案@版号 + 指纹 + 修订号）、切流提交闸
  （选生效方案 + 期望修订号）、切流台账（现行 / 封存行）接详情。
- **访视批次页（邻页）**：亮批次协议版号，与落点对照，拧花亮徽标并拦写操作。
- **台参数页**：只展协议切流口径（`甲·快照表`，只读，拒改）。

## 验收路径（中文页面 + 业务库对照，勿启无头脚本）

1. 查快照表：落点是否入表（现行 / 封存、指纹、修订号）。
2. 复核封存档：再切流后旧行封存、新行现行，封存不回刷。
3. 协议版号核对过关后，回切流场景验证旧协议抓取被拦。
4. 并发双交：一成功一冲突。
5. 印记篡改：直接改库字段后读写被闸拦。
